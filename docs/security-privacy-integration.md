# Security/privacy issue batch: #451, #452, #453, #454

Integrated tenant, auth, league, audit and GraphQL entry points apply a fixed-window authorization-probe budget before database-backed JWT/session/current-role checks. `AUTHORIZATION_RATE_LIMIT_MAX` defaults to 120 requests per IP per minute; existing stricter sign-in and authenticated mutation limits still apply. This bounds the new account-erasure/current-role lookups separately from the existing general API sliding-window limiter. Use the documented trusted-proxy/origin restrictions so client IP evidence is reliable.

The integration branch merges the four independent issue branches with merge commits. It preserves the full effective baseline test list and adds every feature's tests plus a PostgreSQL integration case covering their interaction. Both financial and privacy background jobs/API routers, all new database models/User relations, permissions telemetry and erased-account checks are retained together. Each feature's deployment contract is documented separately:

- `financial-merkle-audit.md`: pgcrypto migration, independently operated append-only public log, hourly publication and critical verification alerts.
- `permission-validation.md`: compiled grants, current-role/ownership checks and shared Redis privilege-canary lockouts.
- `login-anomaly-interceptor.md`: migration, trusted proxy evidence, Redis atomic challenges, mail/feed configuration and callback API contract.
- `encrypted-profile-export.md`: migration, private S3 bucket/recipient decryption, expiry, deletion and retained financial evidence.

For integrated local checks, use a disposable localhost PostgreSQL database named `fantasy_combined`, apply the existing schema and all three new migrations, then set DATABASE_URL and FANTASY_TEST_DATABASE_URL to that same database. Run `npm ci`, `npm run build` and `npm test` in backend. The database integration cases intentionally refuse unrelated hosts/database names. Without FANTASY_TEST_DATABASE_URL, CI skips those cases and runs the complete unit/mock suite; the actual database tests were also run locally against synthetic accounts. No real email, public-log publication, cloud export or financial transaction is exercised by the tests.

The cross-feature case proves that an outdated ADMIN token cannot override the current database role, then erases an account with verified-login history. Its old token is refused, personal activity/trusted locations disappear, and the retained financial entry hashes still verify unchanged. Shared cryptographic/authorization tests include 10,000 synthetic audit entries and measured compiled-policy evaluation below 1 ms (database/network time excluded).

Inherited checks are reported separately from passing feature checks. The unchanged migration safety validator reports three existing errors in `20261023120000_partition_contract_events`; none of these new migrations adds validator errors. The existing resilience suite fails parsing `src/tests/sorobanContractClient.test.ts:247` (unexpected EOF), which is byte-identical to main. The inherited dependency tree audit reports one critical, eight high and three moderate findings, including proxy-addr before 2.0.8. No security workflow is disabled or weakened to hide these findings. Production configuration, independent services, retention policies, Google callback frontend consumption and capacity limits still require the documented deployment setup.
