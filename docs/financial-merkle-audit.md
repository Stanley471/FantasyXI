# Financial Merkle audit (#451)

Apply `backend/prisma/migrations/20261119190000_financial_merkle_audit/migration.sql` through the normal Prisma migration deployment. PostgreSQL must allow the migration owner to install pgcrypto. Run the API as a separate, non-owner database role without trigger-disable, table-owner or schema-DDL privileges. The migration locks and backfills audit evidence atomically and establishes a current-state snapshot of historical transactions. Review migration duration on a staging copy before deployment.

Every transaction insert/update now writes financial evidence in the same database transaction. The database chains canonical PostgreSQL JSON text with SHA-256 and serializes appends with an advisory lock. Source evidence, chain entries and checkpoints reject updates/deletes/truncation; transaction deletes are rejected. Legitimate transaction state transitions append new snapshots. Verification compares current transaction rows with their latest snapshot as well as checking source equality and the complete hash chain. Bypassing capture triggers to alter/delete a transaction is detected too. Separate application audit entries may describe the same event and remain independent evidence.

Configure `FINANCIAL_AUDIT_PUBLIC_LOG_URL` as an independently operated HTTPS append-only public log and `FINANCIAL_AUDIT_PUBLIC_LOG_TOKEN` as its write credential. The external service must implement:

- `PUT {base}/{encoded ISO UTC hour}`: authenticated, immutable/idempotent per hour, accepting `{hour, firstSequence, lastSequence, entryCount, root}`; return a successful HTTP status only after durable publication.
- `GET {base}/{encoded ISO UTC hour}`: the same public root object.
- `GET {base}`: an array of every retained published root object, including old hours. This inventory is necessary to detect deletion of local checkpoint metadata.

Do not host this log in the application database or permit its write credential to overwrite old roots. Only hashes, counts and sequence bounds leave the service; raw financial records are not published. No Stellar transaction is required by this implementation's public-log option.

The existing pg-boss worker publishes closed hourly blocks at minute zero and verifies evidence every minute, with its existing retries/backoff. Explicit verification detects corruption immediately; background detection is bounded by the one-minute schedule and worker availability. Configure existing `ADMIN_ALERT_SLACK_WEBHOOK_URL` and/or `ADMIN_ALERT_EMAILS` for critical integrity alerts. Unavailable publication fails the job rather than recording an unverified success. An external publication followed by a local crash is recovered only if surviving complete evidence reproduces that external checkpoint.

Under both existing API aliases, `GET /financial-audit/roots` lists public root metadata. `POST /financial-audit/verify` and `GET /financial-audit/transactions/:transactionId/proof` require authentication and FINANCIAL_AUDIT_READ. Proofs identify each audit entry for the transaction, its hash, index, tree size, siblings, root and publication. A transaction in an unpublished hour has no published inclusion proof yet (404). Hashes cover the exact stored payload text; do not independently reserialize it before verifying. Leaves use SHA-256(0x00 || entry hash bytes); parents use SHA-256(0x01 || left || right), duplicating odd last nodes.

Checks: `cd backend`, `npm ci`, `npm run build`, `npm test`. Tests include 10,000 synthetic chained entries and Merkle proof edge cases. For the actual PostgreSQL integration test, create a disposable localhost database named `fantasy_451_v3`, apply the repository schema and this migration, and set both DATABASE_URL and FANTASY_TEST_DATABASE_URL to it. The integration case rolls back synthetic records and exercises publication-crash recovery plus trigger-bypassing audit/transaction mutation and deletion. Never target a real account database. The baseline schema migration compatibility test expects a migration history table when using deploy; `prisma db push` alone does not create that history.

Verification currently reads all retained evidence and the external checkpoint inventory; cost grows with history. Benchmark and capacity-plan before large production histories. Compromise of both the database and independent public log is outside this evidence model; unpublished history has no independent anchor yet.
